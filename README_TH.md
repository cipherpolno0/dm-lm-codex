# ระบบฐานข้อมูลคณะสงฆ์และการศึกษา ฉบับใช้งานบนเครื่อง

สร้างจาก `dm_lm_codex.zip` ชุดนี้โดยเฉพาะ ทุกชื่อและรายการเริ่มต้นเป็นข้อมูลสมมติจาก seed และชุดทดสอบของต้นฉบับ

## เปิดอ่านทันที

เปิด `index.html` ด้วยเบราว์เซอร์ โดยไม่ต้องแตก ZIP ย่อย ติดตั้ง npm หรือเชื่อมอินเทอร์เน็ต

- ค้นหาทำเนียบสมมติด้วยชื่อหน่วยงาน ชื่อตำแหน่ง ผู้ดำรงตำแหน่ง ประเภท และวันที่
- ดูลำดับหน่วยงาน บุคคล และประวัติตำแหน่งสมมติจาก seed
- อ่านข้อความจากเอกสาร Word 9 ฉบับและ Markdown 24 ฉบับ
- ดาวน์โหลดเอกสาร Word และแม่แบบ Excel ต้นฉบับได้จากหน้าเว็บ เพราะฝังไฟล์ไว้ใน index.html
- ดูข้อมูล 4 ชีตจากแม่แบบ Excel
- ดูสารบัญ ZIP ย่อย 23 ชุด แบบจำลองฐานข้อมูล 33 ตาราง และผลตรวจชุดทดสอบ

โหมดเปิดไฟล์โดยตรงเป็นโหมดอ่านและค้นหาข้อมูลต้นฉบับ การเพิ่มข้อมูลต้องใช้ตัวรันด้านล่าง ไม่มีการบันทึกข้อมูลหลังบ้านไว้ในเบราว์เซอร์

## เปิดระบบที่เพิ่มและบันทึกข้อมูลได้

ต้องมี Node.js 22 ขึ้นไป ไม่ต้องรัน npm install เพราะตัวรันใหม่นี้ใช้ Node.js standard library และโมดูล .mjs ที่มีใน ZIP

**Windows**: แตกชุด ZIP ที่ส่งมอบ แล้วเปิด `start.bat`

**macOS / Linux / Terminal**: เปิด Terminal ในโฟลเดอร์เดียวกับ index.html แล้วรัน

```bash
node server.mjs
```

ตัวรันจะแสดง:

```text
Open http://127.0.0.1:8082
Local editor access code: <รหัสที่สร้างใหม่>
```

1. เปิด `http://127.0.0.1:8082`
2. เข้าเมนู “จัดการข้อมูลสมมติ”
3. ใส่รหัสจาก Terminal
4. เพิ่มหน่วยงาน บุคคลสมมติ หรือประวัติตำแหน่ง
5. กด “เผยแพร่ทำเนียบ” เพื่อให้ชุดข้อมูลใหม่ค้นหาจากหน้าทำเนียบได้
6. กด “สำรอง JSON” เป็นระยะ

ข้อมูลบันทึกที่ `data/portal-state.json` และคงอยู่เมื่อหยุดและเปิดตัวรันใหม่ รหัสเข้าจัดการเปลี่ยนทุกครั้งที่เปิดตัวรัน เซสชันมีอายุ 60 นาที ตัวรันฟังเฉพาะเครื่องนี้ ไม่ได้เปิดให้เข้าจากคอมพิวเตอร์อื่น

หากพอร์ต 8082 ถูกใช้งาน ให้รัน:

```bash
node server.mjs --port 8083
```

แล้วเปิด `http://127.0.0.1:8083`

การเปิดและหยุดตัวรันใหม่ต้องทำหลังหยุดตัวเก่าด้วย Ctrl+C ไม่ควรเปิดสองตัวรันเพื่อเขียนไฟล์ข้อมูลเดียวกัน

## วิธีทดสอบการใช้ข้อมูล

- ทำเนียบเริ่มต้นมาจาก `tests/public/directory-privacy.test.mjs` มีรายการ Synthetic Learning Office และ Synthetic Head
- เลือกวันที่ในปี 2025 เพื่อดู Synthetic Former Holder และเลือกวันที่ตั้งแต่ 1 มกราคม 2026 เพื่อดู Synthetic Current Holder
- หน่วยงาน 3 แห่งและบุคคล 2 คนมาจาก `prisma/seed.ts` ส่วนชื่อผู้ถือครองในทำเนียบเริ่มต้นมาจากอีก fixture หนึ่ง จึงไม่ใช่ชุดเดียวกันจนกดเผยแพร่จากข้อมูลบนเครื่อง
- ประวัติตำแหน่งของ seed สิ้นสุดในเดือนมิถุนายน 2026 จึงไม่ปรากฏเป็นตำแหน่งปัจจุบันในเดือนตุลาคม 2026
- เมื่อเข้าสู่ระบบ ให้เพิ่มประวัติตำแหน่งตั้งแต่ 1 กรกฎาคม 2026 เป็นต้นไป โดยใช้ชื่อตำแหน่งเดิม หรือสร้างชื่อตำแหน่งสมมติใหม่ แล้วกดเผยแพร่ จากนั้นค้นหาบุคคลนั้นในทำเนียบ
- ระบบปฏิเสธช่วงเวลาของตำแหน่งเดียวกันที่ทับซ้อน และปฏิเสธการย้ายหน่วยงานที่ทำให้ลำดับวนซ้ำหรือผิดประเภท

เวลาในฟอร์มใช้เขตเวลาของเครื่อง วันที่แสดงในหน้าเว็บใช้เวลาไทย วันที่กรองบนหน้าทำเนียบใช้เวลา 00:00 น. ไทย ช่วงดำรงตำแหน่งเป็นช่วงรวมวันเริ่มและไม่รวมเวลาสิ้นสุด ตามโมดูลต้นฉบับ

## ข้อมูลและโมดูลที่เชื่อม

| ส่วนหน้าเว็บ | โมดูลจากต้นฉบับ |
|---|---|
| ทำเนียบสาธารณะ | public-directory-service.mjs |
| เพิ่มและย้ายหน่วยงาน | org-service.mjs |
| เพิ่มบุคคลสมมติ | people-service.mjs |
| เพิ่มประวัติตำแหน่ง | timeline-service.mjs |
| ตรวจสิทธิ์และอายุเซสชัน | authorize.mjs / session.mjs |

ตัวรันเก็บสำเนาข้อมูลใน JSON พร้อมประวัติและ audit ไม่ได้เชื่อม PostgreSQL / Prisma จริง โมดูลเดิมยังอยู่ใน `baseline/` ครบถ้วน ไม่มีการลบหรือแก้เนื้อหาโมดูลต้นฉบับ

หน้าหน่วยงาน บุคคล และประวัติตำแหน่งในโหมดอ่านหรือก่อนเข้าสู่ระบบเป็นสำเนา seed ต้นฉบับ หลังเข้าสู่ระบบจะแสดงข้อมูลล่าสุดบนเครื่อง หน้าทำเนียบที่เปิดผ่านตัวรันจะอ่านชุดเผยแพร่ล่าสุดจาก API เสมอ

## สำรองและกู้คืน

ปุ่ม “สำรอง JSON” ส่งออกชุดข้อมูลปัจจุบันทั้งหมดจากตัวรัน รวมประวัติและ audit หากต้องการกู้คืน ให้หยุดตัวรัน เก็บสำเนาไฟล์ปัจจุบันไว้ก่อน แล้วนำไฟล์สำรองจากแอปนี้มาแทนที่ `data/portal-state.json` จากนั้นเปิดตัวรันใหม่ ไม่ควรใช้ไฟล์ JSON ที่แก้จากแหล่งอื่นหรือข้อมูลบุคคลจริง

หากยังไม่เคยบันทึก ตัวรันจะอ่าน `data/initial.json` เมื่อบันทึกครั้งแรกจะสร้าง `data/portal-state.json` ไฟล์ JSON ที่เสียหายจะทำให้ตัวรันหยุดพร้อมข้อผิดพลาด ไม่เปลี่ยนกลับไปใช้ seed โดยเงียบ ๆ

## ขอบเขตที่ยังไม่รวม

เอกสารและ source ที่อ่านใน index.html เป็นสำเนา ณ วันที่สร้าง ไม่เปลี่ยนตามการแก้ไฟล์ต้นฉบับอัตโนมัติ ข้อความจาก Word แยกเป็นย่อหน้าและแถวตาราง ไม่รักษารูปแบบหน้ากระดาษหรือรูปภาพ; ดาวน์โหลด Word ต้นฉบับเพื่อดูรูปแบบเต็ม

การนำเข้าและ commit Excel, สมัครสอบ, เปลี่ยนสถานะองค์กร, จัดการเอกสารส่วนตัว, audit approval, backup infrastructure และ go-live เต็มรูปแบบยังเป็น baseline สำหรับพัฒนาต่อ ไม่ได้เปิดเป็นฟีเจอร์ของหน้าเว็บนี้ ไม่อ้างว่าระบบ Next.js / PostgreSQL หรือระบบ multi-user พร้อม production

ชุดนี้ใช้ข้อมูลสมมติเท่านั้น คงสถานะ Confirmed / Proposal / Needs Legal Review ตามเอกสารเดิม การเผยแพร่ในตัวรันเป็นการเผยแพร่ชุดทดสอบบนเครื่อง ไม่มีผลเป็นการแต่งตั้งหรือประกาศทางการ

## ทดสอบ

```bash
node --test test_portal.mjs
node test_frontend.cjs
```

การทดสอบ HTTP / การบันทึกข้อมูลผ่าน 6 ชุด การตรวจ JavaScript controller ผ่าน 10 กลุ่ม รายละเอียดและข้อจำกัดของชุดทดสอบต้นฉบับอยู่ใน `INSPECTION_REPORT.md` ยังไม่ได้ตรวจภาพ การคลิก หรือการพิมพ์ในเบราว์เซอร์จริง

## ไฟล์ในชุดส่งมอบ

- `index.html` หน้าเว็บแบบไฟล์เดียว
- `server.mjs` ตัวรันและ API ที่เรียกโมดูลต้นฉบับ
- `start.bat` / `start.sh` ตัวเริ่มระบบ
- `data/initial.json` ข้อมูลสมมติที่แยกจาก seed และ public-directory test
- `data/source.json` ข้อความเอกสาร สารบัญ แบบจำลอง และไฟล์ดาวน์โหลดที่ฝังไว้
- `data/baseline-test-results.json` ผลการรันชุดตรวจต้นฉบับ
- `baseline/` ชุด GoLive PIR ต้นฉบับ 90 ไฟล์
- `source_files/` เอกสารและ ZIP ย่อยจากไฟล์แนบครบ 33 ไฟล์
- `test_portal.mjs` / `test_frontend.cjs` ชุดทดสอบหน้าเว็บใหม่
- `INSPECTION_REPORT.md` รายงานตรวจสอบ
